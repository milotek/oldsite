# milotek.dev

My personal site. Live at <https://furfag.lol/wst20/>.

Static HTML generated by one dependency-free Python script. Content is Markdown
with YAML front matter, one file per thing.

## Adding something

| I want to add    | Drop a file in       | It appears at          |
| ---------------- | -------------------- | ---------------------- |
| A project        | `content/projects/`  | `/work/` and `/work/<slug>/` |
| A blog post      | `content/posts/`     | `/blog/` and the RSS feed |
| A drawing        | `content/art/`       | `/art/`                |
| A standalone page| `content/pages/`     | wherever its `path:` says |

Nav, social links, the 88x31 buttons and the home page copy all live in
`content/site.yaml`.

Then:

```sh
python3 build.py
```

That writes `index.html`, `work/`, `blog/`, `art/`, the pages, `feed.xml`,
`sitemap.xml` and `robots.txt` into the repository root. Those paths are wiped
and rewritten on every build; everything else is hand-authored and left alone.

## Project front matter

```yaml
---
title: Thing I Made
slug: thing
label: Project          # the small line above the title
weight: 40              # sort order on /work/
featured: 2             # 1-4 puts it on the home page, in that order
kind: small             # optional; drops it into the "smaller things" list
year: 2026
role: Author
status: Active
summary: One line, shown on the card.
stack: [Python, Nix]
cover: projects/thing.webp        # relative to assets/img/, optional
cover_fit: contain                # or cover, the default
page: false                       # optional; link straight to GitHub instead
links:
  - label: GitHub
    url: https://github.com/milotek/thing
gallery:
  - src: projects/thing-1.webp
    caption: What this shows.
---

Body copy in Markdown.
```

Projects with no `cover` get a typed placeholder panel, so the grid stays even.

## Images

Screenshots go in `assets/img/projects/`, drawings in `assets/img/art/` as
`<slug>.webp` plus a `<slug>_t.webp` thumbnail. The build doesn't resize
anything, so encode them before committing:

```sh
magick in.png -resize '1600x1600>' -quality 80 assets/img/projects/out.webp
```

## Buttons

`tools/make-buttons.sh` regenerates the 88x31 buttons in `assets/buttons/`.
Add your own PNG there and a matching entry under `buttons:` in
`content/site.yaml`.

## Deployment

GitHub Pages serves this repo from `main` at `/`, so the built output is
committed. Every URL the generator emits is relative, which is what lets the
same files work at a subpath.
